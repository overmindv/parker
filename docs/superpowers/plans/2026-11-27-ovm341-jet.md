# OVM-341 — единая Jet-генерация

> **For agentic workers:** использовать subagent-driven-development для эталонного Parker и requesting-code-review перед merge.

**Goal:** Jet v2.15.0 закреплён во всех Go-модулях workspace; Parker служит проверенным эталоном запросов по сгенерированной live-схеме.
**Architecture:** Parker хранит generated модели в internal/adapter/postgres/generated и использует их внутри internal/outbox. Генерация читает выделенный PostgreSQL Compose после миграций; runtime API/схема и поведение lease/retry/replay не меняются. Другие сервисы получают общую версию и инструкции; перенос их SQL — OVM-342..349.
**Tech Stack:** текущие Go версии, Jet v2.15.0, pgx, PostgreSQL17 Compose.
**Spec:** https://overmindv.atlassian.net/browse/OVM-341 и OVM-340; OpenSpec unify-jet-generation в sibling docs.

## Global Constraints
- Ведущий/владелец parker — Александр Васюков; чужие сервисы только dependency/tooling/docs по прямому поручению пользователя.
- Не менять публичный API, бизнес-схемы и поведение outbox, версии Go, существующие миграции.
- Стандарт: JET_DATABASE_DSN из окружения, JET_SCHEMA=public, make jet-generate и make jet-check; generated код коммитится и не редактируется руками.
- Jet версия ровно v2.15.0, без latest. Остальные зависимости менять лишь из-за MVS/tidy.
- Секреты DSN не печатать, generated output не должен зависеть от имени локальной БД.
- Generated папка internal/adapter/postgres/generated; внутренние schema/model/table подкаталоги допустимы, документировать финальную структуру.
- SQL исключения: DDL миграций, служебные SQL-фрагменты выражений PostgreSQL при отсутствии Jet API. Не оставлять целые DML запросы строками.
- Все тесты писать первыми, но коммитить ОДНИМ последним коммитом после review, код и документацию отдельными группами.
- >7 файлов допускаются для неделимого generated набора и механической унификации; каждый сервис отдельный коммит.

## Review Focus
Сохранение SKIP LOCKED/атомарности claim, защиты stale lease и replay generation;
неутечка DSN; отсутствие генерации из ручной схемы; повторная генерация без дрейфа;
защита текущих файлов от повреждения при недоступной БД; partial outbox stores.
