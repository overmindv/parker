# Границы Parker

Parker — версионированная Go-библиотека, которая встраивается в процесс каждого
сервиса. Она не является сетевым сервисом и не находится на пути запросов, поэтому
её недоступность не может одновременно остановить все приложения.

## Что принадлежит Parker

- lifecycle процесса и graceful shutdown;
- инфраструктурная конфигурация и структурные логи;
- HTTP server, middleware, health/readiness, metrics и tracing;
- PostgreSQL connection/migrations и общие Kafka/outbox primitives;
- CLI и шаблон нового сервиса.

Корневой пакет `github.com/overmindv/parker` — небольшой стабильный фасад для
потребителей. Реализация группируется в `internal/` по ответственности. Изменение
внутренней структуры не должно заставлять сервисы менять импорт.

## Что не принадлежит Parker

Бизнес-сущности, правила доступа, продуктовые workflows, DTO конкретного сервиса,
его SQL-запросы и специализированные retry/ordering guarantees остаются в сервисе.
Если общий primitive требует знания предметной области, это ещё не Parker API.

## Защита от узкого горлышка

Сервисы закрепляют опубликованную версию и обновляются независимо. Публичный API
расширяется только при наличии нескольких потребителей; обратная совместимость
проверяется тестами. Parker не требует центрального runtime, общей БД или
синхронного обновления всех сервисов.
