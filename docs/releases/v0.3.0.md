# Parker v0.3.0 — границы инфраструктуры и безопасный конфиг

## Изменения

- Реализация инфраструктуры разнесена по логическим `internal`-пакетам
  (`env`, `health`, `logging`); публичный фасад корневого пакета сохранён (OVM-300).
- Валидация Kafka TLS в production применяется только к сервису, который создаёт
  Kafka-клиент. Сервис без Kafka (например, users) загружается в production без
  `KAFKA_TLS_ENABLED` и не падает на старте (05a9625).
- Новый публичный `KafkaClientOptions(...KafkaSecurity) ([]kgo.Opt, error)`:
  те же TLS/SASL-опции, что у `NewProducer` и `NewSubscriber`, для собственных
  Kafka-клиентов сервиса. Без аргументов настройки читаются из окружения.
  Нужен сервисам с ручным consumer (например, результаты выполнения кода в tasks),
  чтобы не дублировать разбор `KAFKA_*` и проверки безопасности.

## Совместимость

Go 1.26 и module path `github.com/overmindv/parker` сохранены; зависимости `go.mod`
не изменились относительно v0.2.0. Публичные `Main`, `App`, `Options`, `Runnable`,
`HealthCheck`, `Outbox`, `KafkaSecurity`, `NewProducer`, `NewSubscriber`,
`NewOutboxDispatcher` и `PgOutbox` сохранены. Добавление `KafkaClientOptions`
обратно совместимо.

Поведение изменено намеренно: в production без Kafka-клиента TLS больше не требуется.
Остальные требования безопасности не ослаблены: если сервис создаёт Kafka-клиент,
production по-прежнему требует TLS, а SASL — только поверх TLS.

## Подключение

```bash
go get github.com/overmindv/parker@v0.3.0
go mod tidy
go test -race ./...
go build ./...
```

Коммитить `go.mod`/`go.sum` без `replace` и pseudo-version. Обновление сервисов
независимое: `task-hunter`, `content`, `entities`, `feed`, `media` остаются
на своей версии Parker.

## Миграции владельца

Схема `outbox` не менялась относительно v0.2.0. Сервис, который ещё не применил
lease/retry-миграции, накатывает их из `docs/migrations/202611160001_outbox_leases.sql`
и `docs/migrations/202611160002_outbox_retries.sql` до запуска нового worker.
Порядок rollout и rollback — в [release v0.2.0](v0.2.0.md).

## Проверки релиза

- `make build test lint` — exit 0.
- `go test -race -tags=component ./...` с PostgreSQL и Kafka.
- `scripts/test-kafka-security.sh`.
- `make release-check RELEASE_VERSION=v0.3.0` — потребитель создаётся в temp
  directory, подключает опубликованный тег без `replace` и собирается.
