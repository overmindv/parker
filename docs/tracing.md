# Распределенные трассы

По умолчанию Parker не экспортирует spans. Входящий W3C `traceparent` остается
доступен в `TraceIDFrom` и `SpanIDFrom` и может передаваться дальше без экспорта.
Повторяющийся, неверный или слишком длинный заголовок не принимается как родитель.
`baggage` и `tracestate` в контекст трассировки Parker не импортируются.

## Настройка

| Переменная | Назначение |
| --- | --- |
| `PARKER_OTLP_TRACE_ENDPOINT` | URL приемника OTLP/HTTP. Без явно заданного пути используется `/v1/traces`. Пустое значение выключает экспорт |
| `PARKER_TRACE_SAMPLE_RATIO` | Доля новых трасс от `0` до `1`, по умолчанию `0.1`. При `0` экспорт не отправляет spans, даже если входящий родитель был sampled |
| `SERVICE_NAME` | Статическое имя сервиса для `service.name`, до 64 символов |

При ненулевой доле решение о записи дочернего span следует флагу родителя.
На внешнем входе удаляйте недоверенный `traceparent` на gateway, если выборка
должна определяться исключительно вашей политикой. Используйте private collector.
В staging и production требуется HTTPS с системным доверенным CA. Логин,
пароль, query и fragment в URL запрещены. HTTP-редиректы collector не
выполняются, стандартные `OTEL_EXPORTER_OTLP_*` не переопределяют транспорт.

## Передача контекста

- Входящие HTTP-запросы обрабатываются без изменений в прикладных handlers.
  В span пишутся стандартный метод, статус и зарегистрированный шаблон маршрута.
  Не регистрируйте маршруты из пользовательских данных.
- Для внутреннего HTTP-клиента используйте
  `http.Client{Transport: app.TraceHTTPTransport(nil), Timeout: 5 * time.Second}`.
  Клиент создает span, передает `traceparent` и не передает его при редиректе.
  URL, query, IP и заголовки в span не записываются.
- `app.NewProducer()` и `app.NewSubscriber()` записывают producer/consumer
  spans. `Publish` передает `traceparent`; обработчик и commit offset
  выполняются под одним consumer span, включая повторы. Сигнатуры
  `Publish` и `Handler` не меняются.
- Для прямого использования franz-go доступны `InjectKafkaTrace` и
  `ExtractKafkaTrace`. Схема outbox не меняется: контекст не переживает
  сохранение и последующее чтение outbox без отдельного поля владельца.

В экспорт не попадают тела запросов, код, ответы обработчиков, Kafka
key, value, topic или тексты ошибок. Это ограничение относится к spans,
а не к логам прикладных обработчиков.

## Работа при сбое

Экспорт идет асинхронно. Очередь ограничена 1024 spans, пакет ограничен
128 spans и 1 МиБ, ответ приемника ограничен 64 КиБ. При переполнении
теряется телеметрия, а не запрос или сообщение Kafka. Экспорт не
блокирует ready и не повторяет неудачную отправку.

При завершении процесса очередь сбрасывается после HTTP и воркеров.
На сброс отводится не больше 2 секунд из оставшегося `SHUTDOWN_TIMEOUT`.

```sh
go test -race ./...
go test -tags=component -run '^TestKafkaTraceHTTPToBrokerAndHandler$' .
```

Для второй команды задайте `PARKER_TEST_KAFKA` с адресом выделенного тестового
брокера. Тест создает отдельный топик и проверяет HTTP, producer и consumer
через приемник, декодирующий [OTLP/HTTP](https://opentelemetry.io/docs/specs/otlp/).
