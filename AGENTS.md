# AGENTS.md — правила для агента, работающего с parker

Этот файл дополняет `CLAUDE.md` деталями, важными при изменении кода parker.

## Слои и границы

- `parker` (корень пакета) — **стабильный публичный фасад**: типы контракта и
  тонкие делегирования. Здесь нет реализации. Публичные типы обязаны оставаться
  в корневом пакете (`architecture_test.go` это проверяет).
- `internal/<домен>` — реализация по доменам:
  - `app` — выбор подкоманды, сборка HTTP-сервера, жизненный цикл и ресурсы PostgreSQL/Kafka;
  - `cli` — подкоманды `migrate`/`init`;
  - `servicegen` + `servicegen/template` — генерация каркаса сервиса;
  - `config` — значения по умолчанию, загрузка env и валидация настроек;
  - `convert` — преобразование коллекций между публичными и внутренними типами;
  - `observability` — метрики, трейсинг, OTLP, propagation;
  - `httpkit` — HTTP-сервер и middleware;
  - `requestid` — request_id в контексте;
  - `kafka` — producer/subscriber и TLS/SASL;
  - `postgres`, `migrate` — пул и goose-миграции;
  - `outbox` — transactional outbox и retry;
  - `lifecycle` — Runner и graceful shutdown;
  - `health`, `env`, `logging` — базовые инфраструктурные пакеты.
- `cmd/parker` передаёт управление в `parker.Main`.
- Не расширяй публичный API без нужды; каждое добавление проходится через код-ревью и тестами.
- Добавляя файл в корень, обнови `rootFacadeFiles` в `architecture_test.go`; новый
  код по умолчанию идёт в `internal/<домен>`.

## Жизненный цикл (инвариант)

`parker.Main(run, opts...)`:
1. разбирает подкоманду; 2. загружает `Options` и логгер; 3. собирает `App`; 4. вызывает `run(*App)`;
5. `Runner` запускает HTTP-сервер и фоновые воркеры (runnables); 6. ждёт сигнал SIGINT/SIGTERM
или fatal-ошибку воркера; 7. graceful shutdown с `SHUTDOWN_TIMEOUT`.

Паттерн fatal-остановки: runnable, вернувший ошибку при `ctx.Err()==nil`, логируется и останавливает
весь процесс (как `runWorker`/`serve` в `tasks`). Это поведение не менять без веских причин.

## Конвенции

- Структурные JSON-логи без тел запросов и без чувствительных полей.
- `http.Server`-таймауты задаются из `Options` (`ReadTimeout`/`WriteTimeout`).
- `os.Exit` — только в `cmd/parker/main.go` (возврат кода); пакеты возвращают ошибки.
- Тесты: юнит — `go test -race ./...` без внешних зависимостей; integration/component — тег
  `component` (postgres:17 / kafka) с `PARKER_TEST_DSN`.

## План

Актуальный план разработки — `docs/plan/` (README = индекс, 00–09 = фазы, TASKS.md = чек-лист).
После каждой фазы обязателен зелёный CI (`make build && make test && make lint`).

## Общий agent harness

Для изменения поведения прочитай `../docs/harness/README.md` и релевантную
спецификацию в `../docs/openspec/`. Это sibling-репозиторий `overmindv/docs`,
а не каталог документации этого сервиса. При отдельном checkout и отсутствии
соседа используй локальные правила; нехватку сквозного контекста укажи явно.

- Перед работой зафиксируй `git status --short`; сохраняй чужие незавершённые изменения.
- Работай одним проверяемым срезом; рутинные обратимые решения принимай самостоятельно.
- На смену контракта найди производителей/потребителей и проверь их совместимость.
- Пользовательские сценарии студента и автора/модератора имеют равный приоритет.
- Проверки: `make -C ../infra agent-verify SERVICE=parker DRY_RUN=1` показывает команды.
- В конце приведи фактические результаты и непроверенные места; сохрани следующий шаг.
- Не публикуй, не очищай БД и не отправляй изменения автоматически.
